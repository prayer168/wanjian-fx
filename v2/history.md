# 《萬箭金鐘罩 II：瓦上追風》製作紀錄

這份文件記錄整部片從零到成片的製作過程：使用者的指示（提示詞）、每個階段做了什麼、用了哪些軟體與開源專案、遇到的問題與解法。製作全程由 Claude Code（Anthropic，模型 Claude Opus 5.5）依指示撰寫程式並操作工具完成。本文件會隨製作持續更新。

---

## 一、成品規格

| 項目 | 規格 |
|---|---|
| 形式 | 直接輸出 MP4 影片，不做網頁播放器、畫面不加說明文字、不放標題 |
| 解析度、幀率 | 1920×1080、60 fps |
| 編碼 | H.264（libx264，crf 16），音訊 AAC 320 kbps |

## 四、製作流程

### 1. 渲染管線（`film/`、`render/`）
1. `film/film.html?shot=<場景>` 載入一個場景模組，場景會回傳一串鏡頭（每個鏡頭有長度和攝影機路徑）以及每格更新函式。
2. `window.__renderFrame(i)` 畫出第 i 格。所有動畫、粒子、布料都只依時間決定，所以任何一格單獨渲染結果都一樣。
3. `render/render.mjs` 用 Playwright 開無頭 Chromium，逐格呼叫、截圖，透過管線送進 ffmpeg 編碼。
4. 後製：HDR 多重取樣緒染目標 → 清除無效像素（NaN）→ UnrealBloom 泛光 → ACES 色調映射 → 調色（暗角、色偏、衝擊格黑白反轉、閃白、淡出、底片顆粒）。

### 2. 場景（`film/js/`）
- `sky.js`：程式天空球（漸層、晚霞、雲、月亮貼圖與光暈、5000 顆星點）與遠山。
- `arch.js`：中式建築產生器（歇山頂、斗拱、飛簷、瓦當、城牆城門、牌樓、七層鐘樓、拱橋、烏篷船、柳樹、燈籠），合併成少數幾個網格。
- `nature.js`：地形、竹林（實例化竹子＋透明貼片葉叢）、隨風搖擺的頂點著色器。
- `fx.js`：雨、水花、火星、落葉、霧、煙、v1 的金鐘罩。
- 八個場景：序幕（月下山城）、第一幕（黃昏荒原萬箭）、第二幕（城門與燈市屋脊）、第三幕（月下竹海）、第四幕（雨夜運河石橋，含反射水面與雨滴漣漪）、第五幕（七層鐘樓）、第六幕（雙鐘共鳴：衝擊波掀起全城屋瓦、燈籠熄滅又亮起、雲層被推開見星空）、尾聲（塔頂背對滿月）。

### 3. 寫實角色（`chars/`）
1. `chars/build_char.py` 由 Blender 無介面執行（`blender -b --python chars/build_char.py -- chars/swordsman.json assets/characters/swordsman.glb`）。
2. 讀角色設定 JSON（性別、年齡、肌肉、體重、身高、族裔比例、皮膚、眼睛、眉毛、睫毛、牙齒、髮型），呼叫 MPFB 產生人體並綁上 game_engine 骨架。
3. 服裝不靠現成素材，依身體形狀與骨頭權重自動生成：
   - 貼身部分（上衣、褲、靴、護腕）：複製身體表面 → 平滑 → 沿法線外推 → 邊緣鬆弛去鋸齒；袈裟斜邊用平面切割。
   - 裙擺：從腰到腳踝的車床曲面，左右兩片各自跟隨同側大腿，前襟交疊。
   - 寬袖、腰帶、念珠：程式幾何。
   - 權重：以最近的身體頂點複製，只取真正的骨頭群組。
   - 被衣服蓋住的皮膚刪掉，避免穿模。
4. `chars/preview.py` 用 Eevee 算正面、側面、背面、臉部預覽圖檢查。
5. 劍客：25 歲亞洲男性、馬尾、白袍、箭袖護腕。和尚：中年、肌肉壯碩、光頭、右肩袒露的袈裟、念珠、綁腿。

### 4. 動作與打鬥（`film/js/cast.js`、`people.js`、`fight.js`）
- `cast.js`：從 `rig-test.html` 移植的隱形操偶骨架與招式庫（站、跑、跳、空翻、斬、刺、擋、拳、掌、馬步、受擊、攀牆、對峙），加上時間軸編排（每段：何時、哪一招、從哪移到哪、拋物線高度、面向）。
- `people.js`：每一格把操偶骨架的世界旋轉差量轉到 MakeHuman 骨架上（手臂從 A 字站姿重新對準），手指依握拳量彎曲，劍跟著手；材質：皮膚毛孔法線、絲光布料、濕潤眼球、金屬劍。
- `fight.js`：連招序列、沿路徑移動、對屋頂與橋面做高度探測讓腳踩在瓦上。
- 打擊事件（命中、格擋、落地、鐘鳴）由渲染器匯出成 JSON，交給音效軌對位。
- v3：改用 Mixamo 動作捕捉，並加入招式特效模組 `skills.js`（萬劍歸宗、劍雨、九霄劍陣、劍氣新月、金色掌印、龍爪、一指禪光束、經文光環、千手如來掌）。

### 4.5 運鏡工具（`film/js/cam.js`，v3）
- `pathShot`、`orbitShot`：路徑推軌、環繞（v1 起）。
- `ramp`：變速。動作時間與影片時間分開，一個鏡頭可以慢動作、加速或定格（主程式支援每個鏡頭的 `time` 對應）。
- `crash`：急推（焦距瞬間拉近）。
- `dollyZoom`：推軌變焦（希區考克「迷魂記」鏡頭），攝影機後退的同時焦距拉長，主體大小不變、背景壓縮。
- `overheadShot`：正上方俯視，緩慢旋轉。
- `withWhip`：甩鏡。攝影機快速轉向並加水平動態模糊，放在兩個鏡頭的交界，就成了甩鏡轉場。
- 主程式每格重設攝影機的「上方」向量，避免俯視鏡頭影響下一個鏡頭。

### 4.6 動作捕捉下載（v3）
1. 使用者在內建瀏覽器已登入 Mixamo（Adobe 帳號），密碼不經手。
2. 在 Mixamo 頁面執行腳本，用網站本身的介面搜尋清單上的關鍵字（sword slash、punch combo、hurricane kick、backflip、kip up 等 36 組），依動作描述挑出 66 個。
3. 每個動作送出匯出請求：FBX（fbx7_2019）、無蒙皮（skin: false）、60 fps、不減關鍵格、不勾 In Place。
4. 匯出完成後取得檔案編號，由本機用 curl 存到 `assets/mocap/<分類>_<名稱>.fbx`（S＝劍客、M＝和尚、X＝共用身法）。
5. 匯出必須一個接一個：Mixamo 的進度查詢只回報該角色「最新一個」匯出，若同時跑兩個迴圈，會把別的動作的檔案配到錯的名字。發現後停掉重疊的部分、重新匯出，最後用雜湊確認 67 個檔案互不相同。
6. 試過但行不通的做法：直接觸發瀏覽器下載（內建瀏覽器的下載不會存到可見資料夾）、在本機開接收程式（內建瀏覽器連不到本機）。
7. 依 Mixamo 授權，原始動作檔不放上 GitHub。

### 4.7 動作捕捉重定向與導演系統（v3）
- `film/js/mocap.js`
  - 讀取 Mixamo FBX（three.js FBXLoader），把每一格的骨頭旋轉，以「相對 T 字站姿的世界旋轉差量」套到 MakeHuman 骨架上（MakeHuman 是 A 字站姿，每根骨頭先依方向對準）。共 60 組骨頭，包含每根手指。
  - 角色位移取自 Hips 軌道，並依腿長換算比例。
  - 自動分析每個動作：劍尖、雙拳、雙腳相對骨盆的速度高峰就是「命中點」，腳離地超過 35 公分再落回就是「落地點」。火花、衝擊、震動、音效都依此觸發。
  - 劍掛在右手，依食指到小指指根的方向決定劍身朝向。
- `film/js/director.js`：導演系統。
  - 每一幕寫成一串「節拍」：時長、劍客的招、和尚的招、鏡頭種類、兩人間距、移動量、慢動作倍率、台詞、招式特效。
  - 系統自動排出兩人面對面的動作軌道與每個鏡頭。
  - 鏡頭種類：遠景、中景、低角度、過肩、特寫、俯視、環繞、搖臂、主觀、荷蘭角、跟拍。鏡頭依兩人當下位置即時計算，所以永遠在畫面內。
  - 慢動作節拍會拉長影片時間，並自動把打擊與台詞時間換算回影片時間，讓聲音對得上。
  - 支援換場地與跨高度飛躍，例如從鐘樓平台一躍上塔頂。
- 各幕勝負：
  - 一，荒原：和尚勝（劍雨、金鐘罩、大力金剛掌）
  - 二，城門與屋脊：劍客扳回（龍爪手、羅漢拳、驚鴻一閃、九霄劍陣）
  - 三，竹海：和尚勝（迴風三疊、旋風腿、萬葉化刃、一指禪、獅子吼）
  - 四，雨橋：劍客勝（斷水、般若掌、十二連擊、劃斷念珠）
  - 五，鐘樓：平手（劍陣對鐵布衫、飛躍上塔頂）
  - 六，塔頂：兩敗俱傷（萬劍歸宗對千手如來掌、雙鐘共鳴）

### 5. 聲音（`audio/`）
- `dsp.mjs`：自寫的離線合成工具（濾波器、各色雜訊、風、竹葉、雨、蟲鳴、人聲、銅鐘、風鈴、爆震、風切、木擊、低鳴）。
- `score.mjs`：環境音與打擊音效，依每幕事件時間放置，聲音比畫面早一格。
- `music.mjs`：程式作曲，D 小調五聲音階。古琴（Karplus-Strong 撥弦）、二胡（鋸齒波＋滑音＋顫音＋共振峰）、太鼓、低音弦樂鋪底；同一主旋律貫穿全片；第六幕衝擊前全靜音。
- v3 起 `music.mjs` 改成一首連貫的曲子：全片同一個速度（每分鐘 96 拍）、同一組和弦循環（Dm–B♭–C–Am，每兩小節一個和弦），低音弦樂是一條從頭到尾的聲部、音符平滑滑到下一個和弦；換幕只改變「強度曲線」（0 平靜 → 3 全力），強度決定太鼓密度、撥弦頑固音型和濾波亮度。衝擊後唯一一次轉成 D 大調。
- `mix.mjs`：用 FFmpeg 混音。音效降 3 dB；台詞依 `lines.mjs` 的時間點放入，加短殘響；配樂以側鏈壓縮在台詞下自動壓低。
- `render/build-film.sh`：一鍵完成「渲染各段 → 剪接 → 音效 → 配樂 → 混音 → 響度正規化 → 真峰值限幅 → 合併」，可只重算部分段落或只重做聲音。
- 混音：音效＋配樂 → FFmpeg loudnorm 兩段式正規化到 −14 LUFS → 限幅器 → 與畫面合併。

### 6. 配音（`audio/voice.mjs`、`audio/lines.mjs`）
1. 用 Gemini API 的 Voice design（`POST /v1beta/voices`，`type: prompted`，`language_code: zh-TW`）為兩人各設計一個聲線，只描述固定特質：
   - 劍客：「二十多歲的年輕劍客，說國語帶自然的台灣腔。聲音清亮乾淨、中高音、咬字俐落，語氣裡帶一點瀟灑和傲氣。」
   - 武僧：「四十多歲的少林武僧，說國語帶自然的台灣腔。聲音低沉渾厚、胸腔共鳴很強、沉穩有威嚴，發功時聲如洪鐘。」
2. 每句台詞單獨合成（`POST /v1beta/interactions`，model `gemini-3.8-flash-tts`），情緒寫在該句的 `speech_metadata.style`，例如「被震飛時倒抽一口氣，痛苦咬牙，接著不服氣地讚嘆」，並用 `<gasp>`、`<laugh>`、`<breath>`、`<sigh>`、`<cough>` 標出呼吸與笑聲。
3. 共 26 句（喊招式名、挑釁、受傷喘息、讚嘆、結尾的「明日，再戰。」），全文見 `audio/lines.mjs`。快取在 `out/audio/vo/`，只重做改過的句子。
4. API 金鑰從環境變數 `GEMINI_API_KEY` 讀取，不寫進程式或 GitHub。

### 8. AI 影片路線（`ai/`，2026-11-16 起）

做法是「關鍵畫面圖 → 圖生影片 → 後製」，每個鏡頭只要求一個清楚的動作。

1. **關鍵畫面**（`ai/keyframe.mjs`）：呼叫 Nano Banana Pro（`gemini-3-pro-image` 的 `generateContent`，`responseModalities: ["IMAGE"]`、16:9、2K），可用 `--ref` 帶入角色定裝圖。金鑰只從環境變數 `GEMINI_API_KEY` 讀取。回傳的是 2752×1536 的 JPEG。
2. **圖生影片**（`ai/wan.mjs`）：把關鍵畫面裁到目標尺寸、上傳到 ComfyUI（`/upload/image`），用 `/prompt` 送出工作流程，輪詢 `/history/<id>` 等完成。
   - 工作流程：`UNETLoader`（high noise）→ `LoraLoaderModelOnly`（lightx2v high，強度 1）→ `ModelSamplingSD3`（shift 5）→ `KSamplerAdvanced`（第 0–2 步，cfg 1，euler／simple，保留剩餘雜訊）→ 換 low noise 模型與 LoRA 跑第 2–4 步 → `VAEDecode` → `SaveImage`。條件由 `WanImageToVideo`（起始畫面＋正負提示詞＋VAE）產生。
   - 輸出存成 PNG 逐格圖，再由腳本用 FFmpeg 編成 MP4，後製可以從乾淨的畫面開始。
   - 81 格（16 fps，約 5 秒）。
3. **後製**（`ai/post.mjs`）：FFmpeg 動態補格到 30 fps（`minterpolate`）、放大到 1920×1080、輕微銳化、電影調色（暗部偏冷、亮部微暖、降飽和）、暗角、底片顆粒。
4. **ComfyUI**：可攜版裝在 `D:\ComfyUI\ComfyUI_windows_portable\`，模型集中在 `D:\ComfyUI-models\`，由 `ComfyUI\extra_model_paths.yaml` 指過去。用 `ai/start-comfy.ps1` 啟動在連接埠 **8189**（8188 已被本機另一套 `D:\AI-Local\ComfyUI` 佔用，那是別的專案）。兩套共用同一張顯示卡，`wan.mjs` 送工作前會先等 8188 的佇列清空。

**測試鏡頭的提示詞**（全文在 `ai/prompts/`）
- `test01.key.txt`：月下屋脊、白衣劍客與袒右肩的武僧對峙，中遠景全身。結果偏 CG 插畫感（月亮太大、整體太「乾淨」）。
- `test02.key.txt`：強調「真人實拍的電影劇照、真實皮膚毛孔與布料皺褶、不是插畫或 CG」、自然大小的月亮、膝上中景、50mm 變形鏡頭 f/2。結果是寫實真人質感，接近參考影片的畫面風格。
- `test02.move.txt`（圖生影片）：劍客刺出 → 和尚掌拍劍身迸出火花 → 和尚回掌 → 劍客後仰轉身再斬 → 和尚前臂擋下；手持鏡頭緩慢右繞。

**實測速度**（RTX 5060 Ti 16 GB，4 步）

| 尺寸 | 格數 | 時間 |
|---|---|---|
| 832×480 | 81 | 2 分 45 秒（含第一次載入模型） |
| 1280×720 | 81 | 約 9 分鐘 |

以 720p 計，50 個鏡頭、每個鏡頭平均重做 2–3 次，約 15–25 小時的顯示卡時間。

**測試鏡頭看到的問題**
- 道具不穩：劍在鏡頭後段會變形、換手，最後兩人近身時劍消失；480p 的偏 CG 版本還多出第二把劍。
- 服裝細節會漂移：和尚袒露的手臂換邊、劍客的護腕不見。
- 動作是「看起來像在打」，不是有套路的武術：沒有真正的命中與受力，節奏偏軟。
- 中景的臉可以接受；遠景全身時臉會糊。
- 原始只有 16 fps，補格後快動作邊緣可能有殘影。

對策（正式製作時）：每個鏡頭只做一個動作並縮短到 2–4 秒、在道具出錯前就剪掉；多用首尾格控制（`WanFirstLastFrameToVideo`）；特寫與中景為主、遠景只做氣氛；火花、劍氣、掌印等特效在後製疊加；每個鏡頭多跑幾個種子挑最好的。
